# Claude に貼る用の指示

アプリの「今日の状況をコピー」で出したテキストを Claude に貼り、
返ってきたものを「返答を取り込む」で戻す。その往復を成り立たせるための指示。

## 置き場所

**本文はここには書かない。**正本は
[`src/features/shirei/lib/prompt.ts`](../src/features/shirei/lib/prompt.ts) の `CLAUDE_PROMPT`。

同じ文を 2 か所に持つと、必ずどちらかが古くなる。
古いほうを Claude に入れると、取り込めない返事が返ってきて、
しかも**なぜ取り込めないのかが分からない**という、いちばん困る壊れ方をする。

## 使いかた

「今日」の画面の下、「Claude 側の準備（最初の一度だけ）」を開いて
`Claude への指示をコピー` を押す。それを Claude のプロジェクト
（または Cowork）の**カスタム指示**に入れる。

以後は `今日の状況をコピー` で出したものを貼るだけでよい。

### なぜ毎回貼らないか

会話が進むほど同じ指示が何度も積み上がり、後ろの指示ほど効きが落ちる。
それに、貼り忘れた回だけ取り込めない返事が来るのがいちばん困る。

指示は一度入れたら変えないもの、状況は毎日変わるもの。**寿命が違うので混ぜない。**
だから「今日の状況をコピー」にも指示は足していない。

## 取り込み側との対応

指示は「アプリが受け付ける形」を言葉で説明したものにすぎない。
本当の仕様は [`importplan.ts`](../src/features/shirei/lib/importplan.ts) の
`parsePlanText` にある。

食い違うと指示が嘘になるので、
[`promptcontract.test.ts`](../src/features/shirei/lib/promptcontract.test.ts) で縛ってある。
**このテストが落ちたら、`prompt.ts` の文面も直すこと。**

とくに効いているのは次の 2 つ。どちらも実際に壊れる形をテストにしてある。

| 決まり | 破るとどうなるか |
|---|---|
| 題名を 1 文字も変えない | タスクと結びつかず、ただの文字列になる。**実績が記録されない** |
| 理由の文に時刻を書かない | 予定の行と読み違えて拾われ、「読み取れなかった行」として出る |

## うまくいっているかの見かた

取り込む前の画面に `◯件が既にあるタスク・学習項目と結びつきました` が出る。
**ここが 0 なら題名の写し方が崩れている。**取り込まずに写し直させる。
