# エージェント（Personal Manager）

**公開URL: https://banz-hub.github.io/personal-manager/**

今日やるべきことを **締切・重要度・空き時間から判断して、実行できる予定に落とす** アプリ。
タスクを保存するだけの ToDo アプリにはしない。順位をつけ、**なぜその順位なのかを必ず言葉で返す**。

React + Vite の PWA で、データは端末のなかだけに保存する。

**よてい帳と筋トレログはこのアプリの中に入っている。**別々のアプリだったものを 1 つにまとめた。
ホーム画面に追加したアプリは Safari とデータの置き場が分かれるので、3 つを別々に置いておくと
そこで連携が切れてしまうため。

まとめたのは**画面だけ**で、データの置き場は 3 つに分けたまま。

| 置き場 (IndexedDB) | 正とするもの | 書けるのは |
|---|---|---|
| `personal-manager` | タスク・学習・就活・予定表 | エージェント |
| `yoteicho-app` | カレンダー・時間割・経路・お金 | よてい帳（＋予定表の書き戻しだけエージェント） |
| `kintore-app` | トレーニングの記録 | 筋トレログのみ |

分けたままにしてあるので、**よてい帳・筋トレログで書き出した JSON がそのまま読める。**
どちらが正なのかも消えない。

## 動かす

```bash
npm install
npm run dev
```

- `npm run build` … 本番用に書き出す（`dist/`）
- `npm run test` … Vitest
- `npm run lint` … oxlint
- `npm run icons` … アイコンの PNG を作り直す（形を変えたときだけ）

## 組み立て方（機能を足すとき）

```
src/
  main.tsx           Provider を入れ子にして App を出す
  index.css          色と共通の部品。**色の値を書いてよいのはここだけ**
  app/
    types.ts         Feature の形
    features.ts      積んである機能の一覧 ← 足すときはここ
    App.tsx          外枠。下タブと経路をこの一覧から作る
    MorePage.tsx     下タブに入りきらないものの一覧（自動で並ぶ）
    backup.ts        まとめて書き出す・読み込む
  features/
    shirei/          今日・タスク・学習・就活・ふりかえり・設定
      index.tsx      この機能の登録内容
      pages/ lib/ components/ state/ types.ts
    yotei/           予定・時間割・移動・お金
      index.tsx
      bridge.ts      ほかの機能に見せている入り口
      yotei.css      .ft-yotei の中だけで効く見た目
      pages/ lib/ components/ state/ data/ types.ts
    kintore/         メニュー・記録・実績・目標
      index.tsx  bridge.ts  kintore.css  pages/ lib/ components/ state/ data/ types.ts
```

**画面を 1 つ足すとき**は、その機能の `pages/` にファイルを作り、`index.tsx` の
`routes` に 1 行足す。下タブにも出したいなら `nav` にも 1 行。`App.tsx` は触らない。
画面は `lazy(() => import(...))` で読む。開いたときに初めて落ちてくるので、
画面が増えても最初の読み込みは重くならない。

**機能をまるごと足すとき**は、`features/` の下にフォルダを作って `Feature` を
1 つ書き出し、`features.ts` の配列に足す。下タブの並び順は配列の順そのまま。
`backup` を書いておけば「まとめて書き出す」にも自動で入る。

守っていること:

- **下タブに直に出すのは 4 つまで。**残りは「もっと」に入る（`primary: true` で選ぶ）。
  増えたぶんを機械的に狭くすると、指が届かなくなるため
- **経路は機能ごとに前置きを付ける**（`/yotei/...`, `/kintore/...`）。
  `/settings` のような名前がぶつかるため
- **見た目は機能ごとの css に閉じ込め、`.ft-<機能名>` で囲う。**
  取り込んだ画面のスタイルが、ほかの画面に漏れないようにするため
- **色は `src/index.css` の変数だけを使う。**明暗の切り替えが 1 か所で済まなくなる
- **機能どうしは互いの置き場を直に触らない。**相手の `bridge.ts` を通す。
  置き場の名前があちこちに散ると、誰が書いているのか追えなくなる

## 3 つのアプリの役割

| | 担当（正本） | エージェントから見ると |
|---|---|---|
| **よてい帳** | 予定・授業・移動・時刻表 | 読むだけ。空き時間を出す材料 |
| **筋トレログ** | トレーニングの内容と実績 | 読むだけ。やる日か・何分か・実施済みか |
| **エージェント** | タスク・学習・就活 | 正本として持つ。よてい帳へは**確認のうえ予定だけ書き戻す** |

エージェントが他のアプリに書き込むのは **よてい帳の `events` だけ**（Phase 5 の書き戻し）。
それ以外はすべて読み取り専用なので、連携で既存アプリのデータが壊れることがない。

### なぜ同じオリジンでないと動かないか

データの保存先（IndexedDB）はブラウザによって **オリジンごとに完全に隔離される。**
`banz-hub.github.io` に 3 つとも置いてあるから互いに読める。別のドメインに置くと読めなくなる。

開発中の `localhost:5173` は本番と別オリジンなので、よてい帳のデータは読めない。
そのときは画面の「空き時間を手で入れる」で `19:00〜23:00` のように直接指定して動作を確認する。

## 何ができるか

### 今日

- **今日は何が最優先か**を一文で言う（何をするかだけでなく、なぜかまで）
- 最重要 3 項目（タスクと学習をまたいで選ぶ）。**今日の予定に入らなかったものには印をつける**
- 前日の負荷が高い日は詰め込みの上限を自動で下げ、**下げたことと理由を出す**
- よてい帳から読んだ動かせない予定と、そこから出した空き時間
- 統合ダッシュボード（📅予定 / 🎯タスク / 📚学習 / 🏋️筋トレ / 📊進捗 を一画面で）
- 優先順位をつけたタスク一覧（期限切れ／最優先／重要／継続／任意）と、今日の学習の候補
- 今日の予定表の生成（タスク・学習・筋トレが同じ表に並ぶ）、コマごとの完了記録
- 「今日の状況をコピー」… Claude に貼って相談するためのテキスト

### タスク

一文で書くと、締切・所要時間・分野・重要度を読み取る。

```
金曜までに線形代数のレポート 90分
  → 線形代数のレポート / 数学 / 締切 2026-09-11 / 90分
```

**読み取れなかった項目は埋めずに「確認してください」と出す。**
推測で埋めると、間違った締切のまま気づかずに使うことになるため。

### 学習

科目 → 単元 → 項目 の階層で学習範囲を持つ。段数は決め打ちしていないので、
「数学 → 位相空間論 → 開集合」でも「教職 → 教育心理 → 発達段階 → ピアジェ」でも同じように入る。

いちばん下の項目に **未学習 / 要復習 / 学習中 / 理解 / 習得** の理解度をつける。
最終学習日・学習時間・復習回数・正答率・次の復習日は、**記録から毎回集計して出す**
（項目に書き戻すと、記録と表示が食い違ったときに直せなくなるため）。

試験日を登録すると逆算する。

```
試験まであと2日。範囲3項目のうち習得は0項目で、残り2時間42分ぶんの学習が要ります。
1日あたり1時間21分です。
直近2週間の実績は1日あたり13分です。このままだと間に合わないので、
範囲を削るか、1日1時間21分に増やす必要があります。
直前なので、新しい範囲を進めるより弱点の復習を優先します。
```

試験3日前からは「直前」として扱い、未学習の範囲を広げるより弱点の復習を上に出す。
復習の間隔は理解度で決まる（要復習=1日 / 学習中=2日 / 理解=5日 / 習得=14日）。

### 筋トレ

筋トレログを読んで、今日やる日かを判断し、予定に時間を空ける。
**メニューの中身は決めない。**種目・セット・重量は筋トレログの担当なので、
エージェントは「筋トレを予定に入れる」までしかしない。記録も筋トレログでつける
（エージェントに完了ボタンは置いていない。二重入力になるため）。

筋トレログには週間スケジュールが無いので、やる日かどうかはエージェント側の推定になる。
推定であることが分かる言い方で理由を返す。

```
直近7日で2回。週5回に届いていないので、今日に置きます
3日続けているので、今日は休養に回すのを勧めます
```

前日の負荷が高い日（3日続けている／昨日 60 分以上）は、**詰め込みの上限を自動で 10% 下げる。**
下げたことと理由は必ず画面に出す。

### 「今やる」タイマー

`src/lib/pomodoro.ts`。25 分やって 5 分休む、を 1 セットとして数える（長さは設定で変えられる）。

**解いている問題は「実績が一件も貯まらないこと」。**
それまでは終わってから「何分かかったか」を思い出して打ち込む形だった。
思い出しの数字は当てにならないうえ、打つのが面倒なので結局書かない。
見積もり補正・ふりかえり・週次はどれもその記録を燃料にしているので、
燃料が入らないと全部動かない。**押すのは「今やる」と「終わりにする」の 2 つだけ**にして、
分数はこちらが測る。睡眠が「寝る・起きた」の 2 つで済んでいるのと同じ考え方。

終わると記録の画面が**測った分数で開く。**打ち直す必要はない。

#### 時刻を数えない

経過を 1 秒ずつ足していく作りにはしていない。iPhone は画面を消すと JavaScript を止めるので、
数えている側は止まったぶん遅れる。**押した時刻だけを残して、見るたびに今との差を計算する。**
30 分ぶん止まっていても、復帰した瞬間に正しい値になる。

区間を閉じるのは**気づいた時刻ではなく、終わっていた時刻。**
27 分後にはじめて画面を見ても、実績は 25 分のままで増えない。

#### 見ていない間を作業にしない

その裏返しで、復帰時に「25 分たったので休憩、5 分たったので次の作業…」とまとめて進めると、
**寝ている間に 6 セットやったことになる。**なので進めるのは **1 区間まで。**
次の区間まで終わっているときは止めて、続けるか終わるかを聞く。

```
2時間35分、画面から離れていました。見ていない間は作業にしていません。
[いまから続ける] [ここまでで記録する]
```

#### 分数とセットは別のことを見ている

| | 数えるもの |
|---|---|
| 実績（分） | 実際に作業した時間。途中で切ったぶんも入る。**休憩は入らない** |
| セット | **最後までまわった作業の回数。**途中で切ったものは数えない |

前者は「どれだけやったか」、後者は「集中を最後まで保てたか」。混ぜない。

タイマーは**タスクと学習だけ。**筋トレの記録は筋トレログの担当なので置かない（二重入力になる）。
走らせられるのは**同時に 1 件だけ**で、2 つめを押すと理由を出して断る。

コマの長さとタイマーの長さは合わせていない。20 分のコマでも 25 分でまわる。
タイマーは**実行中の刻み**で、コマの長さは**予定を組むときの単位**だから。
早く終わったら「終わりにする」を押せばよい。

設定の `休憩を挟むまでの作業` (60分) と混ざらないよう、別の項目にしてある。
あちらは予定表を組むとき、こちらは実行中と、見ている単位が違う。

### 睡眠

押すのは 3 つだけ。**時刻は入力させない。**手で入れる手間があると続かないし、
あとでまとめて入力すると思い出しで書くので数字が当てにならない。

| ボタン | すること |
|---|---|
| 寝る | 区間を開く |
| 起きた | 区間を閉じる |
| 二度寝する | 同じ晩の続きとして区間を足す |

二度寝を別の記録にせず、**同じ晩の 2 つ目の区間**として持つ。
「2 回寝た」ではなく「1 晩のうちに 1 回起きた」と数えたいため。
睡眠時間は閉じた区間の合計なので、途中で起きていた時間は入らない。

```
23:10 寝る → 06:00 起きた → 06:15 二度寝 → 07:40 起きた
→ 8時間15分（6:50 + 1:25）二度寝1回 目標比 +45分
```

押した時刻を**そのまま**残す。丸めない。評価と助言は毎回そこから計算し直す。

**これを今日の予定に反映する。**変えたときは理由を必ず画面に出す。

1. **起きた時刻＋支度から今日を始める。** 8 時起きの前提で組んだ予定は、
   10 時に起きた日には最初から破綻している
2. **目標の就寝時刻から逆算して夜の終わりを決める。**
   終わりを決めないと、足りないぶんが毎晩そのまま睡眠から引かれる
3. **寝不足の日は詰め込みの上限を 10% 下げる。**筋トレのあとと同じ考え方

評価は**長さと細切れ具合の 2 つだけ**で決める。寝つきや深さは測れないので入れない。
測っていないものを混ぜると、数字の意味が分からなくなる。

助言も**記録から言えることだけ**。「早く寝ましょう」は誰にでも言えるので言わない。

同じ日に記録が 2 つできること（昼寝＋夜、押し間違い）があるので、
その日を代表するのは**いま寝ている最中のもの、無ければいちばん長いもの**。
5 分に満たない記録は押し間違いとみなして残さない。

### 就活

企業ごとに選考段階・志望度・予定を持ち、**締切を近い順に、期限切れは別に**出す。
就活の締切はこちらの都合で動かせないので、見落としが致命傷になるため。

選考段階から「次にやること」が決まる（ES準備なら「ESを仕上げて提出する」）。
ES締切や面接を登録すると、そこから逆算した作業の**候補**が出る。
**勝手には登録しない。**要るものだけ選んでタスクにする。

企業比較では、**調べた事実と自分の見立てを必ず分ける。**
「年間休日125日」は調べれば同じ答えになる事実、「ワークライフ ★4」はあなたの評価。
両方を混ぜた総合点は出さない。混ぜた瞬間、どちらが効いたのか説明できなくなるため。
未記入は 0 ではなく「—」で、並べ替えでは常に最後に来る。

### 通知

**アプリを閉じていても確実に鳴らす方法は、ブラウザだけでは無い。**
Web Push を使うには通知を配る側のサーバーが要るが、このアプリはサーバーを持たない。
そこで効く順に 3 段構えにしてある（`src/lib/reminders.ts`）。

| | 閉じていても鳴るか | 対応 |
|---|---|---|
| **1. 端末カレンダーに入れる（.ics）** | **鳴る** | どの端末でも。iPhone ではこれが本命 |
| 2. 通知トリガー（TimestampTrigger） | 鳴る | Android の Chrome など。iOS Safari は非対応 |
| 3. アプリを開いている間のタイマー | 鳴らない | どの環境でも動く保険 |

1 は「今日の予定表」の **「カレンダーへ」** で、アラーム付きの .ics を書き出す。
端末側のアラームなので、ブラウザを閉じていても鳴る。
3 のときは画面の中にも **ポップ表示** を出すので、通知が使えない環境でも目に入る。

iPhone は「ホーム画面に追加」して起動した状態でないと、そもそも通知が使えない。
設定の画面に、いまの端末で何ができるかを出している。

### 朝と夜の案内・聞く

ボタンを自分で探させない。時間帯に合わせて「次にこれを押す」を **1 つだけ**出す。
押すものが無いときは何も出さない（常に何か出ていると見なくなるため）。
データの書き出しから 30 日たつと、何より先に催促する。

「聞く」欄に一文入れると、これまでの判断エンジンに振り分けて答える。

```
今日どうすればいい？ → まず「正則関数」から。試験まであと1日。目安は30分です。
                       使える時間は 10時間25分。この順にやるのがおすすめです…
締切やばい？         → 今週の締切があります。[就活] B社 ES締切 — あと2日 …
```

**分からない聞き方をされたら、それらしい作り話をしない。**答えられる範囲を並べて聞き直してもらう。

### 探す・分ける・繰り返す

- **検索**（画面右上の 🔍）… タスク・学習項目・企業・選考の予定を横断で探す。
  ひらがな／カタカナ、大文字小文字、全角半角の違いは無視する
- **手順に分ける**… 大きなタスクをひな形（レポート／試験勉強／発表／ES／読書）や
  自由記述で割る。締切は最後の手順に合わせて 1 日ずつ前倒しする。
  **候補として出すだけで、選んだものだけが実際のタスクになる**
- **繰り返し**… 毎日／毎週◯曜／毎月◯日。終えると次の回が自動で作られる
  （毎日すこしずつ進める「継続タスク」とは別のしくみ）
- **学習項目の付け替え**… 別の単元の下へ移せる。**自分自身と自分の配下は選べない**
  （親子が輪になると、ツリーをたどる処理が終わらなくなるため）。移動先の末尾に入り、
  元いた場所の並びは詰め直される
- **期限切れの棚卸し**… 1 件ずつ「今日にする・来週にする・やめる」を決める

### 色の使い分け

色は 2 つの軸で使っている。**混ぜると、どちらの意味で色を見ればいいのか分からなくなる。**

| 軸 | 出る場所 | 色 |
|---|---|---|
| **締切の近さ** | タスク一覧の左の帯 | 期限切れ／最優先／重要／継続／任意 |
| **コマの種類** | 予定表の左の帯とラベル | タスク／学習／筋トレ／予定 |

同じ画面の同じ位置に両方を出すことはしない。

**色だけで区別させない。**帯と同じ色のラベルを必ず文字でも出す
（明るい場所・色が見分けにくい目・白黒では、色の意味が消えるため）。
題名がそのまま種類の名前になるとき（「筋トレ」）はラベルを出さない。同じ言葉が 2 つ並ぶだけなので。

いま時刻が入っているコマは背景を変える。測っている最中のコマは、上の札と同じオレンジの枠にする。

### 予定表の手直し・取り込み

生成した予定は手で直せる。◀▶ で 15 分ずらし、−＋ で長さを変え、時刻の欄で開始時刻を直に決め、
✕ で消す。**ほかのコマと重なる動きはしない。完了したコマは実績なので触れない。**
重なるときは「『英語』と重なります」のように理由を出す。

ドラッグにしていないのは、**iPhone で確実に動かないから。**
HTML5 のドラッグはタッチで反応せず、自前で実装すると取りこぼしが出る。
時刻を選ぶ形なら片手でも正確に決められる。

「今日の状況をコピー」で Claude に相談し、返ってきた予定を「返答を取り込む」で戻せる。
これで往復が閉じる。取り込みも**書いてあることをそのまま作る**だけで、
題名から推測して勝手に紐づけたりはしない（取り違えると関係ないタスクの実績になるため）。

往復を成り立たせる指示は「Claude 側の準備（最初の一度だけ）」から取り、
Claude のプロジェクトのカスタム指示に入れる。**状況のテキストには足していない。**
一度入れたら変えない指示と、毎日変わる状況とで寿命が違うため。
詳しくは [docs/claude-prompt.md](docs/claude-prompt.md)。

### 空き時間の使い道

よてい帳の「やること」と「趣味」を、今日の空き時間の**長さ・場所**と突き合わせて出す。
並べ方はよてい帳の `suggest.ts` をそのまま呼んでいる。**2 通りに計算しない。**
よてい帳の画面とここで違うものが出ると、どちらが正しいのか分からなくなる。

**読むだけで書かない。**「済み」にするのも増やすのもよてい帳側。正本は向こうにある。

**押すと、その空き時間の予定に入る。**いちばん早い隙間ではなく、選んだ空き時間の中に置く。
「この時間にこれをやる」と決めて押しているのに、朝いちへ飛ばされては選んだ意味が無い。
入るのはエージェントの予定表だけで、よてい帳には書かない。

すでにこの画面の別のところに出ているものは重ねない（筋トレログが「今日やる」と
言っている日に、趣味の「筋トレ」まで出ると 2 回出る）。休む日には趣味として戻ってくる。

**長期の勉強は「やること」に入れない。**「やること」は 1 回で終わる用事のためのもので、
所要時間がそのまま「1 回の長さ」になる。500 時間と書くとどの空き時間にも入らない。
資格や試験の勉強は**学習**に入れる。そちらは 1 回 30 分ずつに割られる。

### ふりかえり

完了・未完了・実績時間・計画とのズレを集計し、**次の計画をどう変えるか**を返す。
未完了は翌日に繰り越せる（締切は動かさず、先送り回数だけ数えて優先順位を上げる）。
筋トレの実績も「今日動かした時間」に足して見る。

**週次**では 3 つのアプリの記録をまとめる。タスク（完了率・延期率・見積もり精度）、
学習（時間・分野別・習得数）、就活（ES・説明会・面接・選考中の社数）、
筋トレ（回数・時間・休養日）。そのうえで **「来週改善すべきこと」を最大 3 つ**返す。
3 つに絞るのは、全部並べると結局どれも手をつけないため。

**月ごと・年ごと**は「続いているかどうか」を見るためのもの。所見は出さず、
積み上げ棒グラフ（タスク／学習／筋トレ）と増減だけを見せる。

## 優先順位の決め方

外部の AI は使わない。`src/lib/priority.ts` で決定論的にスコアを出す。
オフラインで動き、毎回同じ答えになり、テストが書ける。
そのかわり **理由を言葉で返せること** を条件にしている。

| 材料 | 重み |
|---|---|
| 期限を過ぎている | +130 |
| 今日が締切 | +115 |
| 明日が締切 | +65 |
| あと 3 日 | +42 |
| 今週が締切 | +24 |
| 重要度 | ×22（高=66 / 中=44 / 低=22） |
| 未着手で締切が近い | +14 |
| 着手済み | +8 |
| 先送りした回数 | ×12（上限 36） |
| 継続タスクの放置日数 | ×4（上限 28） |
| 就活の締切 | +10 |

この重みなので、**「重要度が低いが今日締切」は「重要度が高いが 1 週間後」より上に来る。**

グループ分けはスコアだけで決めない。「期限切れ」「今日締切」という誰が見ても分かる事実を先に使い、
そこに当たらないものだけスコアで振り分ける。説明できない順位を出さないため。

## 学習の優先順位

`src/lib/study.ts`。タスクと同じく決定論的に出す。

| 材料 | 重み |
|---|---|
| 試験まであと3日以内 | +100 |
| 7日以内 | +60 |
| 14日以内 | +35 |
| 30日以内 | +18 |
| 試験範囲に入っている | +15 |
| 要復習 | +45 |
| 未学習 | +30 |
| 学習中 | +25 |
| 習得済み | −20 |
| 重要度 | ×18 |
| 復習の予定日を過ぎている | +35 |
| ◯日やっていない | ×2（上限 20） |
| 正答率が 60% 未満 | +25 |
| 試験直前の未学習 | −25 |

最後の 3 つ（復習期日超過・放置日数・低正答率）は **合計 45 で頭打ち** にしてある。
どれも「この項目は今ぐらついている」という同じことを別の角度から見ているだけで、
たいてい同時に立つ。そのまま足すと同じ事実を三重に数えることになり、
学習項目がタスクを不当に押しのけてしまう。

タスクと学習のスコアは同じ幅（おおむね 0〜250）に収まるよう重みを決めてあるので、
そのまま混ぜて 1 つの予定表に並べられる。**片方の重みを変えるときは、もう片方との釣り合いも見ること。**

## 予定表の作り方

大事なのは並べることではなく **詰め込まないこと。** `src/lib/scheduler.ts`。

- 空き時間の **80% まで**しか作業を入れない（設定で 50〜95%）。残りは予備として空ける
- 続けて 60 分作業したら休憩を挟む
- 今日 17:00 締切のタスクは 17:00 までに終わる位置にしか置かない
- 入りきらなかったものは、その理由を残す

100% にはできない作りにしてある。予定どおりに進まない日を吸収する余地が無いと、
1 つ遅れただけで全部崩れるため。

## 見積もりの補正

`src/lib/estimate.ts`。予定と実績の比を貯めておき、次の見積もりに反映する。

```
数学課題  予想 60 分 → 実績 90 分  … が 3 回続いたら
次回の割り当ては 90 分になる
```

- 中央値を使う（1 回だけ長かった日に引きずられないため）
- そのタスクのログが 2 件に満たなければ、同じ分野のログで代用する
- 補正は 0.7〜2.0 倍で頭打ち（暴走を防ぐ）

## AI をどう扱うか

**アプリの中に対話 AI は入れない。** 静的サイトから LLM API を直接呼ぶと、
API キーがユーザーの端末に露出する（隠す場所が無い）。隠すにはサーバーが要る。

かわりに 2 層にしてある。

1. **決定論エンジン**（このアプリ）… 優先順位・理由・予定表・レビューの所見まで。無料でオフライン
2. **対話**（Claude）… 「今日の状況をコピー」で渡して相談する

## データの持ち方

IndexedDB（`personal-manager` / `state`）に 11 種類。

| | 中身 |
|---|---|
| `Task` | やること。締切・見積もり・重要度・状態 |
| `DayPlan` | その日に生成した予定表。日付ごとに 1 つ |
| `TaskLog` | 予定と実績。見積もりの補正にだけ使う |
| `DailyReview` | 日次レビュー |
| `Settings` | 1 日の使い方の設定 |
| `StudyNode` | 学習の階層。科目・単元・項目を 1 つの型で表す（`parentId` でつなぐ） |
| `Exam` | 試験。日付と範囲（ノードを選ぶと配下すべてが範囲） |
| `StudySession` | 学習 1 回の記録。時間・手応え・正答数 |
| `Company` | 企業。選考段階・志望度・**事実**（facts）と**見立て**（ratings）を別に持つ |
| `SelectionEvent` | 選考の予定。ES締切も説明会も面接もこれ |
| `WeeklyReview` | 週次レビュー。計算した時点の数字をそのまま残す |

**筋トレの記録は持たない。**正本は筋トレログなので、必要なときに読むだけ。

`StudyNode` を 4 段の型に分けなかったのは、段数が科目によって違うため。
型を段ごとに分けると、浅い科目に空の段ができるか、深い科目が入らなくなる。

`Company` の `facts` と `ratings` を別の型にしてあるのは、**混ぜると区別が消えるから。**
同じ欄に入れると、あとで見返したときにどちらだったのか分からなくなる。

## 注意点

- データは端末のブラウザの中にしかない。**iOS は長く開かないと消すことがある**ので、
  月に一度は `設定 → データ → 書き出す` で JSON を保存する
- 移動時間は「場所が変わる予定の間から 60 分引く」という粗い引き当て。

- `src/lib/bridge/yoteicho.ts` の時間割の組み立ては、よてい帳の `src/lib/schedule.ts` を
  必要な範囲だけ写したもの。別リポジトリなので共有できていない。
  **よてい帳側を直したらここも見直すこと。**
- 筋トレログの記録には、**開始したまま終了を押し忘れた 936 分のセッション**が実際にあった。
  そのまま平均に入れると予定が壊れるので、5〜180 分の外は捨ててセット数から見積もり直している
  （`src/lib/bridge/kintore.ts`）。
- 筋トレログは 1 日の区切りをずらせる（本人の設定は 3 時）。**深夜はエージェントの「今日」と 1 日ずれる。**
  どちらの日の話かを画面に出して区別している。

## よてい帳への書き戻し（唯一の書き込み）

`src/lib/bridge/yoteicho-write.ts`。よてい帳には手で入れた予定と、
作り直せない 785 便の時刻表がある。だから安全側の決まりを先に置いてある。

1. **触るのは `source === 'pm'` のイベントだけ。**手で入れた予定には一切触れない
2. 触るのは指定した 1 日ぶんだけ
3. 書き込むのは `events` キーだけ。時刻表・区間・授業・支出には触れない
4. 書く直前にもう一度読み直す（画面を開いてからの変更を消さないため）
5. **書く前に検算し、エージェント以外のイベントが 1 件でも減っていたら中止する**

5 が最後の砦で、ここを通らない書き込みは起きない。
実行前には「作る N 件 / 差し替え M 件 / 触らない K 件」を全部見せて、押してもらってから書く。
「エージェントが作った予定をすべて取り消す」で元に戻せる。休憩と予備は送らない。
