# エージェント（Personal Manager）

**公開URL: https://banz-hub.github.io/personal-manager/**

**開いたらすぐ、その日の予定と、その日やることが分かる**アプリ。
予定（授業・バイト・就活…）は種類ごとに色を付けて時刻順に並べ、やることはタスクの一覧から選んでリストにする。
学習・就活・睡眠・筋トレの記録と、週ごとのふりかえりも同じアプリで持つ。

React + Vite の PWA で、データは端末のなかだけに保存する。

**よてい帳と筋トレログはこのアプリの中に入っている。**別々のアプリだったものを 1 つにまとめた。
ホーム画面に追加したアプリは Safari とデータの置き場が分かれるので、3 つを別々に置いておくと
そこで連携が切れてしまうため。

まとめたのは**画面だけ**で、データの置き場は 3 つに分けたまま。

| 置き場 (IndexedDB) | 正とするもの | 書けるのは |
|---|---|---|
| `personal-manager` | タスク・学習・就活・睡眠 | エージェント |
| `yoteicho-app` | カレンダー・時間割・経路・お金 | よてい帳のみ |
| `kintore-app` | トレーニングの記録 | 筋トレログのみ |

分けたままにしてあるので、**よてい帳・筋トレログで書き出した JSON がそのまま読める。**
どちらが正なのかも消えない。

## 動かす

```bash
npm install
npm run dev
```

- `npm run build` … 本番用に書き出す（`dist/`）
- `npm run test` … Vitest
- `npm run lint` … oxlint
- `npm run icons` … アイコンの PNG を作り直す（形を変えたときだけ）

## 組み立て方（機能を足すとき）

```
src/
  main.tsx           Provider を入れ子にして App を出す
  index.css          色と共通の部品。**色の値を書いてよいのはここだけ**
  app/
    types.ts         Feature の形
    features.ts      積んである機能の一覧 ← 足すときはここ
    App.tsx          外枠。下タブと経路をこの一覧から作る
    MorePage.tsx     下タブに入りきらないものの一覧（自動で並ぶ）
    backup.ts        まとめて書き出す・読み込む
  features/
    shirei/          今日・タスク・学習・就活・ふりかえり・設定
      index.tsx      この機能の登録内容
      pages/ lib/ components/ state/ types.ts
    yotei/           予定・時間割・移動・お金
      index.tsx
      bridge.ts      ほかの機能に見せている入り口
      yotei.css      .ft-yotei の中だけで効く見た目
      pages/ lib/ components/ state/ data/ types.ts
    kintore/         メニュー・記録・実績・目標
      index.tsx  bridge.ts  kintore.css  pages/ lib/ components/ state/ data/ types.ts
```

**画面を 1 つ足すとき**は、その機能の `pages/` にファイルを作り、`index.tsx` の
`routes` に 1 行足す。下タブにも出したいなら `nav` にも 1 行。`App.tsx` は触らない。
画面は `lazy(() => import(...))` で読む。開いたときに初めて落ちてくるので、
画面が増えても最初の読み込みは重くならない。

**機能をまるごと足すとき**は、`features/` の下にフォルダを作って `Feature` を
1 つ書き出し、`features.ts` の配列に足す。下タブの並び順は配列の順そのまま。
`backup` を書いておけば「まとめて書き出す」にも自動で入る。

守っていること:

- **下タブに直に出すのは 4 つまで。**残りは「もっと」に入る（`primary: true` で選ぶ）。
  増えたぶんを機械的に狭くすると、指が届かなくなるため
- **経路は機能ごとに前置きを付ける**（`/yotei/...`, `/kintore/...`）。
  `/settings` のような名前がぶつかるため
- **見た目は機能ごとの css に閉じ込め、`.ft-<機能名>` で囲う。**
  取り込んだ画面のスタイルが、ほかの画面に漏れないようにするため
- **色は `src/index.css` の変数だけを使う。**明暗の切り替えが 1 か所で済まなくなる
- **機能どうしは互いの置き場を直に触らない。**相手の `bridge.ts` を通す。
  置き場の名前があちこちに散ると、誰が書いているのか追えなくなる

## 3 つのアプリの役割

| | 担当（正本） | エージェントから見ると |
|---|---|---|
| **よてい帳** | 予定・授業・移動・時刻表 | 読むだけ。1 ページ目の「予定」に出す |
| **筋トレログ** | トレーニングの内容と実績 | 読むだけ。やる日か・何分か・実施済みか |
| **エージェント** | タスク・学習・就活・睡眠 | 正本として持つ |

エージェントは他のアプリに**書き込まない**。すべて読み取り専用なので、連携で既存アプリのデータが壊れることがない。

### なぜ同じオリジンでないと動かないか

データの保存先（IndexedDB）はブラウザによって **オリジンごとに完全に隔離される。**
`banz-hub.github.io` に 3 つとも置いてあるから互いに読める。別のドメインに置くと読めなくなる。

開発中の `localhost:5173` は本番と別オリジンなので、よてい帳のデータは読めない。
そのときはブラウザの開発ツールで `yoteicho-app` にテスト用の予定を入れて確認する（同じ画面のよてい帳のタブで入れてもよい。同じオリジンなので読める）。

## 何ができるか

### 今日

1 ページ目。**その日の予定と、その日やることが一目で分かる**ことだけを目的にしている。
上から 3 つしか置かない。

| 節 | 中身 |
|---|---|
| **予定** | **0 時〜24 時のタイムスケジュール。**よてい帳の授業・予定を種類の色で、睡眠を斜線で、**空き時間を点線の枠と長さ**で置く。上に空きの合計・いまから先の空き・いちばん長い空きを出す |
| **今日やること** | タスクの一覧から選んだもの。チェックで済みにする。「今やる」でタイマーが動く |
| **睡眠** | 何時から何時まで寝たかを 1 行で。入っていなければ時刻 2 つを入れる欄が出る |

- 上の **‹ ›** で前の日・次の日へ。**「週で見る」**で、その日の週のカレンダーへ飛ぶ
- やることは、その場で書いて追加するか、**「リストから選ぶ」**でタスクの一覧から選ぶ。
  締切の近いものほど上に出る
- 終わらなかったものは **「残り N 件を翌日へ」**で次の日のリストに送る。締切は動かない。
  送り忘れた日があっても、次に開いた日に「前の日までの残り」として拾える

タイムスケジュールは**長さをすべて実際の時間に比例させる**（1 時間 24px、1 日で 576px）。
空いている時間を縮めると、空きの大きさが見た目で比べられなくなるため。
空き時間は「予定も睡眠も入っていない 15 分以上の時間」をそのまま出すだけで、何を入れるかは決めない
（`lib/timeline.ts`）。睡眠が入っていない日は、寝ている時間も空きに数えてしまうので、そのことを画面に出す。

**時間の割り当てはしない。**以前はここで空き時間から予定表を自動で組んでいたが、
使っていて見づらいので外した（2026-09-18）。何時に何をやるかは自分で決める。

### 予定（週・月のカレンダー）

「予定」のタブは**週の表示がはじめ**。縦が時刻、横が月〜日で、予定を時刻の位置に種類の色で置く。

- 週は**月曜はじまり**（ふりかえりの週と区切りをそろえる）
- 縦の幅はふだん 8 時〜22 時。その週に朝早い・夜遅い予定があれば、そこまで広げる
- **時刻が重なった予定は横に並べる。**重ねて描くと下の予定が読めなくなる
- 今日の列は色が付き、いまの時刻に赤い線が引かれる
- 日付や予定を押すと、下にその日の一覧が出る（予定なら編集が開く）。「この日を開く」で 1 ページ目のその日へ

「月」に切り替えると月のカレンダーになり、日ごとに予定の数だけ種類の色の点が付く。

### タスク

すべてのやることの一覧。ここで「今日のリストに入れる」を押すと、1 ページ目の「今日やること」に出る。
どの日のリストに入っているかはタスクの `pinnedDate` 1 つで持つ（1 つのタスクが載る日は 1 日だけ）。

一文で書くと、締切・所要時間・分野・重要度を読み取る。

```
金曜までに線形代数のレポート 90分
  → 線形代数のレポート / 数学 / 締切 2026-09-11 / 90分
```

**読み取れなかった項目は埋めずに「確認してください」と出す。**
推測で埋めると、間違った締切のまま気づかずに使うことになるため。

### 学習

**学習はタスクとして持ち、時間はタイマーで記録する。**習熟度・優先度・試験からの逆算は持たない（2026-09-19）。

- 学習の画面で「何を勉強するか」と分野を書いて追加する（例: 基本情報技術者 / 資格）
- 分野ごとに並び、それぞれ**累計時間と最後にやった日**が出る。時間はタイマー（今やる）で測った記録から出す
- **その日にやるものは自分で選ぶ。**学習の画面の「今日やる」か、1 ページ目の「リストから選ぶ」で今日のリストに入れる
- 学習は何日も続けるものなので、**今日のリストでチェックしても学習そのものは終わらない。**
  その日のぶんが済んだ印（`checkedOn`）だけ付き、次の日にはまた選べる。やめるときは学習の画面で「この学習を終える」

中身は `Task` に `study: true` を付けたもの。タスクの画面には出さず、学習の画面にだけ出す。
前の版の学習項目（習熟度つき）が残っているときは、学習の画面の「学習のタスクに移す」で移せる。
実際に勉強する単位（いちばん下の項目）だけを移し、記録の付いていない項目は消す。

### 筋トレ

筋トレログを読んで、今日やる日かを判断し、予定に時間を空ける。
**メニューの中身は決めない。**種目・セット・重量は筋トレログの担当なので、
エージェントは「筋トレを予定に入れる」までしかしない。記録も筋トレログでつける
（エージェントに完了ボタンは置いていない。二重入力になるため）。

筋トレログには週間スケジュールが無いので、やる日かどうかはエージェント側の推定になる。
推定であることが分かる言い方で理由を返す。

```
直近7日で2回。週5回に届いていないので、今日に置きます
3日続けているので、今日は休養に回すのを勧めます
```

前日の負荷が高い日（3日続けている／昨日 60 分以上）は、**詰め込みの上限を自動で 10% 下げる。**
下げたことと理由は必ず画面に出す。

### 「今やる」タイマー

`src/lib/pomodoro.ts`。25 分やって 5 分休む、を 1 セットとして数える（長さは設定で変えられる）。

**解いている問題は「実績が一件も貯まらないこと」。**
それまでは終わってから「何分かかったか」を思い出して打ち込む形だった。
思い出しの数字は当てにならないうえ、打つのが面倒なので結局書かない。
ふりかえり・週次はどれもその記録を燃料にしているので、
燃料が入らないと全部動かない。**押すのは「今やる」と「終わりにする」の 2 つだけ**にして、
分数はこちらが測る。

終わると、**測った分数とセット数をそのまま記録する。済みにはしない。**
25 分やって続きは明日、はよくあるので、済んだかどうかはチェックで本人が決める。
押してすぐ止めた（1 分未満）ものは残さない。

#### 時刻を数えない

経過を 1 秒ずつ足していく作りにはしていない。iPhone は画面を消すと JavaScript を止めるので、
数えている側は止まったぶん遅れる。**押した時刻だけを残して、見るたびに今との差を計算する。**
30 分ぶん止まっていても、復帰した瞬間に正しい値になる。

区間を閉じるのは**気づいた時刻ではなく、終わっていた時刻。**
27 分後にはじめて画面を見ても、実績は 25 分のままで増えない。

#### 見ていない間を作業にしない

その裏返しで、復帰時に「25 分たったので休憩、5 分たったので次の作業…」とまとめて進めると、
**寝ている間に 6 セットやったことになる。**なので進めるのは **1 区間まで。**
次の区間まで終わっているときは止めて、続けるか終わるかを聞く。

```
2時間35分、画面から離れていました。見ていない間は作業にしていません。
[いまから続ける] [ここまでで記録する]
```

#### 分数とセットは別のことを見ている

| | 数えるもの |
|---|---|
| 実績（分） | 実際に作業した時間。途中で切ったぶんも入る。**休憩は入らない** |
| セット | **最後までまわった作業の回数。**途中で切ったものは数えない |

前者は「どれだけやったか」、後者は「集中を最後まで保てたか」。混ぜない。

数えるだけで出さないと意味が無いので、**2 か所に出す。**

| 場所 | 出るもの |
|---|---|
| 1 ページ目 → 「今日やること」の見出しの横 | その日のセット数と、**タイマーで測った時間** |
| ふりかえり → 今週の「集中」 | その週のセット数と 1 日あたり |

今日のほうは**走っている最中のぶんも足す。**終えるまで 0 のままだと、
3 セットやったあとに画面を見て「今日 0 セット」と出ることになる。
記録に残るのは終えたときだが、やった事実はもう起きている。

**手で付けた記録は 0 セットとして数える。**タイマーを使っていないので、
セットという単位がそもそも無い。同じ理由で「測った時間」にも入れない
（あれは「今日どれだけ動いたか」ではなく「今日どれだけ測れたか」の数字）。

タイマーより前に作った週次には数字が無い。**0 とは出さない**
（「その週はやらなかった」に見えるため）。「この週はタイマーがまだありませんでした」と出す。

#### 測るのは、記録が残るものだけ

「今やる」は、**今日のリストに入っているタスク**にだけ出る（今日の日付を見ているときだけ）。
タスクなら実績のログが残り、ふりかえりに効く。よてい帳の予定や筋トレには出さない
（正本が向こうにあり、測ってもこちらに何も残らないため）。

走らせられるのは**同時に 1 件だけ**で、2 つめを押すと理由を出して断る。
タスクの見積もりとタイマーの長さは合わせていない。見積もり 20 分のタスクでも 25 分でまわる。
早く終わったら「終わりにする」を押せばよい。

### 睡眠

**「何時から何時まで寝たか」を入れる。**1 ページ目の睡眠の欄か、睡眠の画面で入れる。
睡眠の画面では日付を選べるので、入れ忘れた日もあとから入れられる。

- 日付は**起きた日。**寝た時刻が起きた時刻より遅ければ、前の日の夜に寝たものとして数える
  （23:30 → 7:00 は前の晩、1:00 → 8:00 は当日）
- 同じ日にもう一度入れると**置き換わる。**直すたびに記録が増えないように
- 5 分未満・16 時間超は入力の間違いとみなして保存しない

はじめは「寝る・起きた」のボタンで押した時刻を残す形だったが、押し忘れた晩が空欄になるので変えた
（2026-09-18）。記録の形（寝ていた区間の並び）は同じなので、ボタンの頃の記録もそのまま読める。

評価は**長さと細切れ具合の 2 つだけ**で決める。寝つきや深さは測れないので入れない。
測っていないものを混ぜると、数字の意味が分からなくなる。
助言も**記録から言えることだけ**。「早く寝ましょう」は誰にでも言えるので言わない。

### 就活

企業ごとに選考段階・志望度・予定を持ち、**締切を近い順に、期限切れは別に**出す。
就活の締切はこちらの都合で動かせないので、見落としが致命傷になるため。

選考段階から「次にやること」が決まる（ES準備なら「ESを仕上げて提出する」）。
ES締切や面接を登録すると、そこから逆算した作業の**候補**が出る。
**勝手には登録しない。**要るものだけ選んでタスクにする。

企業比較では、**調べた事実と自分の見立てを必ず分ける。**
「年間休日125日」は調べれば同じ答えになる事実、「ワークライフ ★4」はあなたの評価。
両方を混ぜた総合点は出さない。混ぜた瞬間、どちらが効いたのか説明できなくなるため。
未記入は 0 ではなく「—」で、並べ替えでは常に最後に来る。

### 通知

**アプリを閉じていても確実に鳴らす方法は、ブラウザだけでは無い。**
Web Push を使うには通知を配る側のサーバーが要るが、このアプリはサーバーを持たない。
そこで 2 段構えにしてある（`lib/reminders.ts`）。

| | 閉じていても鳴るか | 対応 |
|---|---|---|
| 通知トリガー（TimestampTrigger） | 鳴る | Android の Chrome など。iOS Safari は非対応 |
| アプリを開いている間のタイマー | 鳴らない | どの環境でも動く保険 |

知らせるのは、**時刻付きの締切の少し前**。
開いている間は画面の中にも **ポップ表示** を出すので、通知が使えない環境でも目に入る。

iPhone は「ホーム画面に追加」して起動した状態でないと、そもそも通知が使えない。
設定の画面に、いまの端末で何ができるかを出している。

### 探す・分ける・繰り返す

- **検索**（画面右上の 🔍）… タスク・学習項目・企業・選考の予定を横断で探す。
  ひらがな／カタカナ、大文字小文字、全角半角の違いは無視する
- **手順に分ける**… 大きなタスクをひな形（レポート／試験勉強／発表／ES／読書）や
  自由記述で割る。締切は最後の手順に合わせて 1 日ずつ前倒しする。
  **候補として出すだけで、選んだものだけが実際のタスクになる**
- **繰り返し**… 毎日／毎週◯曜／毎月◯日。終えると次の回が自動で作られる
  （毎日すこしずつ進める「継続タスク」とは別のしくみ）
- **学習項目の付け替え**… 別の単元の下へ移せる。**自分自身と自分の配下は選べない**
  （親子が輪になると、ツリーをたどる処理が終わらなくなるため）。移動先の末尾に入り、
  元いた場所の並びは詰め直される
- **期限切れの棚卸し**… 1 件ずつ「今日にする・来週にする・やめる」を決める

### 色の使い分け

**予定の種類ごとに色を決めてある。**色を決めるのは `yotei/lib/tone.ts` の 1 か所だけで、
1 ページ目・週のカレンダー・月のカレンダー・予定の一覧がすべてここを通す。
2 か所で決めると、同じバイトが片方では水色、片方では灰色になる。

| 種類 | 色 |
|---|---|
| 授業（時間割） | 緑 |
| 私用・旅行 | ピンク |
| バイト | 水色 |
| 就活 | オレンジ |
| 試験 | 赤 |
| その他 | 灰色 |

試験は、よてい帳の予定の種類に「試験」を足してある（予定を入れるときに選ぶ）。
学習の画面で入れた試験も、同じ赤で出る。

**色だけで区別させない。**帯と同じ色のラベル（「授業」「バイト」）を必ず文字でも出す
（明るい場所・色が見分けにくい目・白黒では、色の意味が消えるため）。

タスク一覧の左の帯は、これとは別に**締切の近さ**を表している（期限切れ／最優先…）。
同じ画面の同じ位置に両方を出すことはしない。

### ふりかえり

完了・未完了・実績時間・計画とのズレを集計し、**次の計画をどう変えるか**を返す。
日ごとの完了・未完了は、その日の「やること」に入れたもので数える。未完了は翌日のリストへ送れる（締切は動かさない）。
筋トレの実績も「今日動かした時間」に足して見る。

**週次**では 3 つのアプリの記録をまとめる。タスク（完了率・延期率・見積もり精度）、
学習（時間・分野別・習得数）、就活（ES・説明会・面接・選考中の社数）、
筋トレ（回数・時間・休養日）。そのうえで **「来週改善すべきこと」を最大 3 つ**返す。
3 つに絞るのは、全部並べると結局どれも手をつけないため。

**月ごと・年ごと**は「続いているかどうか」を見るためのもの。所見は出さず、
積み上げ棒グラフ（タスク／学習／筋トレ）と増減だけを見せる。

## AI をどう扱うか

**アプリの中に対話 AI は入れない。** 静的サイトから LLM API を直接呼ぶと、
API キーがユーザーの端末に露出する（隠す場所が無い）。隠すにはサーバーが要る。

かわりに 2 層にしてある。

1. **決定論エンジン**（このアプリ）… ふりかえりの所見まで。無料でオフライン
2. **対話**（Claude）… 相談したいときは、外の Claude に自分で聞く

## データの持ち方

IndexedDB（`personal-manager` / `state`）に 11 種類。

| | 中身 |
|---|---|
| `Task` | やること。締切・見積もり・重要度・状態・**どの日のリストに入れたか**（`pinnedDate`） |
| `DayPlan` | 以前の版で自動で組んだ予定表。いまは作らない。残っている日はふりかえりで読むだけ |
| `TaskLog` | タイマーで測った実績（分数とセット数） |
| `DailyReview` | 日次レビュー |
| `Settings` | タイマーの長さ・睡眠の目標・連携と通知の設定 |
| `StudyNode` | 前の版の学習項目。いまは作らない（学習は `Task` の `study: true`）。移し替えまで残る |
| `Exam` | 前の版の試験。いまは作らない（試験はよてい帳の予定の「試験」で入れる）。残っていれば 1 ページ目に「終日」で出る |
| `StudySession` | 前の版の学習記録。いまの学習の時間は `TaskLog` に残る |
| `Company` | 企業。選考段階・志望度・**事実**（facts）と**見立て**（ratings）を別に持つ |
| `SelectionEvent` | 選考の予定。ES締切も説明会も面接もこれ |
| `WeeklyReview` | 週次レビュー。計算した時点の数字をそのまま残す |

**筋トレの記録は持たない。**正本は筋トレログなので、必要なときに読むだけ。

`Company` の `facts` と `ratings` を別の型にしてあるのは、**混ぜると区別が消えるから。**
同じ欄に入れると、あとで見返したときにどちらだったのか分からなくなる。

## ネットに公開する

`main` に push すると GitHub Actions がビルドして公開する。

リポジトリは **public**（Pages が無料プランでは public 限定のため）。
ソースコードに個人情報は無いので問題ないが、**実データの JSON は絶対にコミットしない**
（`.gitignore` 済み。バックアップは private の `banz-hub/yoteicho-data` に置く）。

## 注意点

- データは端末のブラウザの中にしかない。**iOS は長く開かないと消すことがある**ので、
  月に一度は `設定 → データ → 書き出す` で JSON を保存する
- `src/lib/bridge/yoteicho.ts` の時間割の組み立ては、よてい帳の `src/lib/schedule.ts` を
  必要な範囲だけ写したもの。別リポジトリなので共有できていない。
  **よてい帳側を直したらここも見直すこと。**
- 筋トレログの記録には、**開始したまま終了を押し忘れた 936 分のセッション**が実際にあった。
  そのまま平均に入れると予定が壊れるので、5〜180 分の外は捨ててセット数から見積もり直している
  （`src/lib/bridge/kintore.ts`）。
- 筋トレログは 1 日の区切りをずらせる（本人の設定は 3 時）。**深夜はエージェントの「今日」と 1 日ずれる。**
  どちらの日の話かを画面に出して区別している。

## よてい帳には書き込まない

**エージェントはよてい帳に書き込まない。**予定の正本はよてい帳で、こちらは読むだけ。

以前は、自動で組んだ予定表をよてい帳へ書き戻す機能があった（`source: 'pm'` の印を付けた予定だけを触る作り）。
予定表を組むのをやめたので、書き戻しも外した（2026-09-18）。
前に書き戻した予定が残っていれば、よてい帳の予定として普通に見え、普通に消せる。

## 作らないと決めたもの

- **複数端末での同期（2026-09-08 に不要と判断）。** サーバーが要り、「データを端末の外に出さない」
  という前提そのものを変えることになる。端末を移すときは
  設定の「3つまとめて書き出す／読み込む」で JSON を 1 つ持っていく。
  使うのは 1 台なので、それで足りる。
- **時間の割り当て（予定表の自動作成）（2026-09-18 に外した）。** 空き時間に作業を詰めて予定表を組む機能があったが、
  画面が込み入って見づらくなったので外した。やることはリストにして、何時にやるかは自分で決める。
  外したコードは git の履歴に残っている（`f5d945c` までの `src/features/shirei/lib/scheduler.ts` など）
- **学習の習熟度・優先度・試験からの逆算（2026-09-19 に外した）。** 学習はタスクにして、やるものは自分で選ぶ
